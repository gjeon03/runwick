# 환경변수와 MCP 변경을 적용하는 세션 새로고침

조사일: 2026-11-05 · 상태: **공식 문서와 로컬 CLI 도움말 확인, 실제 재개·환경 갱신 시험은 미실행**

사용자는 공통 환경변수 설정과, 기존 대화를 유지하면서 환경변수·MCP 변경을 적용하는 새로고침을 요청했다. 이 문서는 구현 가능성을 판단할 근거와 검증 항목을 기록한다. 설정 파일·비밀값은 읽거나 수정하지 않았고 실제 CLI 세션은 시작·종료하지 않았다.

## 확인한 지원 기능

| 도구 | 확인한 사실 | 근거 |
| --- | --- | --- |
| Claude Code | `--resume`로 ID 또는 이름을 지정해 대화 재개. `--fork-session`은 새 ID를 만드는 별도 옵션 | [공식 CLI 문서](https://code.claude.com/docs/en/cli-reference), 로컬 2.1.318의 `--help` |
| Claude MCP | `/mcp`에서 서버 재연결 가능. `list_changed` 알림으로 도구 목록 갱신도 지원 | [공식 MCP 문서](https://code.claude.com/docs/en/mcp#dynamic-tool-updates) |
| Codex CLI | `codex resume`에 세션 ID를 지정하고 작업 경로·설정 옵션을 전달할 수 있음 | [공식 명령 문서](https://learn.chatgpt.com/docs/developer-commands?surface=cli#codex-resume), 로컬 0.164.0의 `resume --help` |
| Codex 실행 구조 | 공유 background server를 사용하지 않는 `--no-daemon` 옵션이 존재 | [공식 명령 문서](https://learn.chatgpt.com/docs/developer-commands?surface=cli), 로컬 도움말 |
| Codex App Server | `config/mcpServer/reload`는 디스크의 MCP 설정을 다시 읽고 로드된 thread의 갱신을 예약 | [공식 App Server 문서](https://learn.chatgpt.com/docs/app-server) |

MCP 서버 재연결·도구 목록 갱신은 CLI 프로세스의 환경변수 전체가 바뀐다는 뜻이 아니다. 특히 공유 서버에 붙는 CLI는 화면 프로세스를 재시작해도 실행 엔진이 유지될 수 있다. Runwick은 실제로 환경을 소비하는 실행 계층까지 확인해야 한다. 이 판단은 위 실행 구조에 근거한 설계상의 추론이며 end-to-end 동작을 확인한 결과는 아니다.

## 구현 방향

Runwick의 세션 식별자와 provider 대화 ID를 유지하고, 그 아래의 실행 시도만 교체할 수 있게 한다. 이름이나 `--last`로 대상을 추측하지 않고 저장한 정확한 provider ID를 사용한다. 모델·권한·작업 경로 등 사용자가 선택한 실행 조건을 보존한다.

MCP만 갱신하는 경우에는 해당 버전의 공식 재연결 경로를 사용할 수 있는지 확인한다. 환경변수가 바뀌는 경우에는 새 환경으로 실제 실행 엔진을 갱신하는 경로를 검증한다. `--no-daemon` 또는 전용 실행 서버 등의 방식은 비교 후보이며 채택 결정이 아니다. 다른 세션이 쓰는 공유 프로세스를 무조건 종료하지 않는다.

새로고침 전에는 재개 가능 여부와 대화 저장 상태를 확인한다. 실패 시 새 빈 대화나 fork로 대체하지 않고 원래 기록·핀·작업 공간을 유지한다. 재개는 실행 중이던 셸 명령이나 메모리 상태를 그대로 복원한다는 보장이 아니다. 중단된 도구 호출을 임의로 다시 실행하지 않는다.

`.env`는 프로젝트 도구가 읽는 설정 방식으로 존중한다. Runwick이 임의로 셸 코드로 실행하거나 모든 CLI가 자동 로딩한다고 전제하지 않는다. 환경값 우선순위와 실제 적용은 실행 어댑터에서 확인할 항목이다.

## 구현 전 검증할 조건

1. **동일 대화 재개:** 정확한 ID로 돌아오며 이전 대화·핀·작업 경로와 모델·권한 설정이 유지되는지 확인한다.
2. **환경 갱신:** 합성된 비밀값이 아닌 테스트 변수의 추가·변경·삭제가 새 CLI와 새 도구 프로세스에 반영되는지 확인한다. 실제 비밀값은 출력하지 않는다.
3. **MCP 갱신:** 신규 서버·변경된 도구 목록·변경된 환경을 읽는 stdio 서버를 구분해 시험한다. 인증 필요와 연결 실패를 성공과 구분한다.
4. **작업 중 처리:** 응답 또는 도구 실행 중 완료 후 적용, 사용자가 중단 후 적용, 전송하지 않은 입력 처리와 기록 수집을 검증한다.
5. **실패 복구:** 잘못된 설정·누락된 재개 ID·시작 실패에서도 기존 기록을 보존하고, 중복 실행이나 다른 대화 선택이 없는지 확인한다.
6. **영향 범위:** 한 세션을 새로고침해도 다른 CLI·일반 터미널·개발 서버·미저장 문서가 영향을 받지 않는지 확인한다.

기능 구현과 지원 버전 확정은 이 검증 이후에 수행한다. 현재 조사만으로 모든 설정 변경을 중단 없이 즉시 적용할 수 있다고 보장하지 않는다.
