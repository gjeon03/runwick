# 사용 흐름·수용 기준·요구사항 추적

상태: **제품/UI 설계 검증 기준 · 구현 테스트 결과 아님** · 2026-11-05

[제품 요구사항](product-spec.md)의 RW 번호와 [화면 명세](ui-spec.md)의 S 번호를 연결한다. 각 흐름은 UI 디자인에서 실제 화면 연결로 보여주고, 구현 때는 해당 실패 조건까지 시험한다.

## F01 — 처음 열어서 작업 시작

진입 S00 → 폴더 선택 → 기본 공간이 있는 S01 → CLI 선택 → S02.

- 사용자에게 프로젝트명·workspace명·팀명·역할 입력을 모두 요구하지 않는다. 기본값으로 시작하고 이후 이름 변경 가능.
- Git이 없는 문서 폴더도 파일/셸 사용 가능. CLI 미설치·인증 실패는 도구 상태로 표시하고 파일 열람은 가능.
- 같은 폴더를 다시 선택하면 기존 프로젝트로 이동. 경로 별칭·symlink·같은 저장소 worktree 중복 판정은 실제 canonical 경로와 저장소 식별을 검증한다.
- 완료 기준: AI 호출 없이 탐색을 시작하고, 팀이나 자동 분석을 켜지 않아도 CLI 한 세션을 쓸 수 있음.

## F02 — 여러 프로젝트와 세션 오가기

S01의 전체/별 전환 → 프로젝트/공간 선택 → S02의 살아 있는 터미널/문서 복원 → 새 세션 또는 분할.

- 즐겨찾기 해제·목록 필터 변경·탭 닫기는 실행을 종료하지 않음. 긴 이름·작은 폭에서 사이드바 가로 스크롤 없음.
- 같은 공간에 새 세션을 추가하면 같은 폴더를 사용한다. 공간이 바뀌면 파일 트리·열린 문서·세션이 그 공간 기준으로 전환.
- 현재 입력 중인 한글 조합·선택·스크롤이 다른 세션의 입력으로 전송되지 않아야 함.
- 완료 기준: 빠른 전환이 기존 CLI 화면·색상·실행 수명에 영향을 주지 않음.

## F03 — 선언 없이 협업 시작

S02에서 평소 요청 → 현재 CLI가 위임 필요 판단 → Runwick 실행 연산 → S02에 협업 요약 등장 → S04에서 작업자 확인.

- 세션이 한 팀에만 속한다는 검사 없음. 새 팀·대표 세션·alias를 먼저 등록하지 않음.
- 허용된 범위 내의 위임은 설정한 정책을 따름. AI가 하나의 CLI로 해결하면 불필요한 작업자나 단계가 생기지 않음.
- CLI 부팅 후 첫 지시가 미전달이면 `전달 대기` 또는 `전달 확인 필요`, 승인 대화면이면 해당 CLI로 이동. ‘작업 중’으로 위장하지 않음.
- 같은 요청을 재전송해도 접수 ID가 같으면 같은 시도로 응답. 전송 직후 연결 끊김은 확인 후 처리하며 중복 worker를 만들지 않음.
- 완료 기준: 평소 대화에서 위임·결과 반환까지 가능하고 각 요청의 출처와 결과를 열 수 있음.

## F04 — 작업자 보기·후속 요청·직접 개입

S04 작업자 클릭 → S05 미리보기 → 직접 대화 또는 탭 유지 → 다시 맡기기 → S04 결과.

- 미리보기만으로 키 입력이 작업자에게 전달되지 않음. 직접 대화 시 자동 입력 보류 표시.
- 바쁜 작업자에 후속 요청은 대기열로 이동. 중단하고 새 지시를 보내려면 별도 행동. 기존 시도가 자동 취소되지 않음.
- 작업자 탭 고정은 부모/결과 관계를 유지. 닫기와 실행 종료를 구별.
- 미리보기를 닫아도 직접 조작 상태가 남으면 S02/S04에 반환 수단이 보여야 함.
- 다른 공간의 미리보기는 현재 파일 트리를 유지. 탭 유지/결과 파일 편집은 소유 공간으로 전환하고 이전 공간으로 돌아갈 수 있어야 함.
- 새 배정 보류는 미전달 대기열에도 적용. 이미 수행 중인 결과는 저장하고, 명시적 재개 때 입력권·경로·선행 결과를 재확인. 취소한 시도는 다시 시작하지 않음.
- 완료 기준: 사용자 입력과 AI 지시가 한 프롬프트에 섞이지 않고, 사용자 추가 지시도 같은 시도 이력에 연결됨.

## F05 — 병렬 변경·worktree·통합

S02/S04에서 분리 요청 → S10 기준/포함 범위 확인 → 공간 생성 → 개별 CLI 실행 → S11 결과·diff → 통합 준비.

- 더러운 기본 공간의 변경은 자동 stash·복사하지 않음. 선택 commit 또는 확인한 patch가 기준.
- Git이 아니면 현재 공간의 순차 작업으로 이어갈 수 있음. Git worktree 생성 성공 후 CLI 실패는 CLI만 재시도.
- 의존성/`.env`/포트 준비와 worktree 생성은 별도 상태. 준비 명령 실패 후 기본 공간에서 잘못 실행하지 않음.
- 같은 파일/공유 설정을 동시에 바꿔야 하면 분리 또는 순차 처리. review는 어떤 revision/스냅샷을 읽었는지 보존.
- 통합 충돌은 작업/결과를 남기고 해결·보류 가능. 미커밋·미푸시·실행 중 작업이 있는 공간은 자동 제거하지 않음.
- 완료 기준: 결과 기준과 통합 대상이 명확하고 작업 중단이 다른 공간의 변경을 지우지 않음.

## F06 — 내 확인이 필요한 일 놓치지 않기

자식 실행의 승인/질문 → S02 배지·S06 행 → 해당 S05/S02 요청 → 답변 → 현재 상태 갱신.

- 화면에 안 열린 자식과 다른 공간의 연결 작업도 집계. 대표가 응답을 끝냈어도 남은 실행 수가 보임.
- 오래된 승인 클릭은 현재 요청과 일치하지 않으면 전송하지 않음. 요청 ID를 모르면 원래 CLI 화면으로 이동.
- 알림이 포커스를 빼앗지 않으며, 읽음 처리로 검증 통과/일 완료가 되지 않음.
- 완료 기준: 사용자가 해야 할 행동을 구분하고 답변이 정확한 실행/요청에만 도달함.

## F07 — 실패 뒤 처음부터 반복하지 않고 이어가기

S04 실패/중단 → S11 초안·오류·이전 검증 확인 → `이어서 수정` → 새 시도 → 결과 연결.

- 완료된 분석·파일·검토 근거를 재사용하되 현재 입력/파일 버전과 맞는지 확인. 수정된 전제에 의존한 단계만 다시 수행.
- 오래된 테스트 통과는 변경된 파일에 재사용하지 않음. 이전 시도 결과는 삭제하지 않음.
- 대기 API의 timeout, 실제 작업 한도 도달, 프로세스 종료, 결과 품질 문제를 구별.
- 시작/전달 여부가 불확실하면 조회부터 하고 자동 반복 실행하지 않음. 한도 도달 시 저장된 결과와 재개 가능한 부분 표시.
- 완료 기준: 재시도 대상·재사용 근거·달라진 실행을 알 수 있고 동일 부작용을 맹목적으로 반복하지 않음.

## F08 — CLI 옆에서 문서 편집

S01 파일 → S03 문서 → 터미널과 나란히 → 수정 → AI가 같은 파일 외부 수정 → 비교 → 저장.

- 한국어 IME 조합, undo/redo, 여러 줄 붙여넣기, 저장 인코딩을 검증.
- 외부 변경과 미저장 편집이 동시에 있으면 자동 덮어쓰기 금지. 비교 중 또 바뀌면 저장 전에 다시 확인.
- 공간 전환/탭 닫기/창 닫기 후 버퍼 보존. 동일 파일명이어도 실제 공간의 경로가 유지.
- 완료 기준: IDE 전체 기능 없이도 문서를 안전하게 확인·편집하고 CLI 작업을 계속할 수 있음.

## F09 — 대화 찾기·핀 고정

S02에서 기록 열기 또는 통합 검색 → S07 범위 선택 → 결과 → 앞뒤 문맥 → 핀 → 나중에 핀에서 원문.

- 터미널 버퍼에서 사라진 대화도 이미 수집했으면 검색. 수집 안 된 범위는 표시.
- 동일한 문장이 여러 번 나와도 원본 메시지를 혼동하지 않음. 터미널 발췌는 원문 식별 불가 상태를 정직하게 표시.
- 원본이 없으면 핀 스냅샷은 유지. 핀 해제가 원문을 지우지 않음.
- 완료 기준: 위키/임베딩/자동 AI를 꺼도 한국어·영문·코드 문구 검색과 핀이 작동.

## F10 — 기록을 지식과 다음 작업으로 연결

S07 핀/세션 → S08 위키 초안 또는 수동 기록 → 변경 비교/적용 → S09 타임라인 → 인계 자료 선택 → 기존 또는 새 CLI.

- 자동 요약은 원문과 구분, 근거와 생성 시각 유지. 상충하는 결정은 확인 필요.
- 위키 직접 편집 뒤 생성된 제안은 기준 버전을 확인하고 재비교. 수동 영역 보호.
- 인계 자료는 선택한 기록/문서 버전/경로이며 모든 프로젝트 대화를 자동 첨부하지 않음.
- 기존 CLI에 전달하면 현재 입력권/준비 상태를 확인. 새 CLI에는 인계 문서임을 표시하고 원래 provider 대화의 재개로 위장하지 않음.
- 교차 프로젝트 협업의 원문/파일은 실제 소유 프로젝트에 귀속. 타 프로젝트의 위키 자동 분석에 협업 연결만으로 본문 전체가 들어가지 않음.
- 완료 기준: 언제 무엇을 왜 했는지부터 실제 원문·파일·실행으로 되돌아갈 수 있음.

## F11 — 창 닫기·재실행·재부팅

S02 실행 중 창 닫기 → 메뉴 막대 S06 → 앱 재열기 → 실행 연결. OS 재부팅 후에는 S01/S09 기록 복원 → 재개할 세션 선택.

- 창만 닫은 경우 같은 실행인지 ID/PID 등 실제 증거로 확인. 새 프로세스를 띄워 놓고 ‘연결 복구’라고 부르지 않음.
- 명시적 ‘작업까지 종료’는 연결된 자식과 독립 실행의 영향 목록을 보여주고 실제 종료 상태를 확인.
- UI crash/Core restart/PTY 소유 프로세스 종료/OS reboot를 각각 시험. 재개 불가 시 원문 보존과 이유 표시.
- 대표가 예기치 않게 죽으면 새 배정을 보류하고 이미 수행 중인 자식 결과를 보존. 무기한 고아 작업을 방치하지 않고 S06에서 복구/중지 가능.
- UI/Core가 재시작돼도 배정 보류 상태와 미전달 대기열을 유지. 사용자가 재개하기 전 대기 요청을 몰래 전달하지 않음.
- 완료 기준: 살아 있는 실행 연결, 동일 provider 대화 재개, 기록 보기의 세 경로가 구별됨.

## F12 — 환경/MCP 변경을 현재 대화에 적용

S13 공통 설정 저장 → 적용 대기 세션 확인 → S12 새로고침 → 응답 후 적용 또는 중단 선택 → S02 같은 대화.

- 사전 확인 실패는 기존 실행을 종료하지 않음. 환경 diff는 키·변경 여부만 표시하며 비밀값을 로그에 남기지 않음.
- 대상 세션 배정 잠금과 실행 세대 변경으로 이전 완료 이벤트가 새 시도를 마치지 않게 함.
- MCP만 연결 가능한 경로와 환경을 다시 읽기 위해 프로세스 재개가 필요한 경로를 구별. 공유 daemon 때문에 무관한 세션을 종료하지 않음.
- 일부 MCP 인증 실패는 ‘전체 적용 완료’ 대신 항목별 상태. 원래 provider ID가 달라지면 성공으로 처리하지 않음.
- 완료 기준: 대화·핀·작업 공간·관련 협업 기록이 유지되며 지원되지 않는 재개는 명확히 알려줌.

## F13 — 배터리와 자동 작업 확인

S13 프로젝트 자동 분석 켜기 → 기록 변경/idle → S06 보류/실행 → 전원 분리 → 처리 단위 저장 후 다음 자동 작업 보류.

- 자동 분석을 끄면 새 AI 작업이 생기지 않음. 대화 저장·키워드 색인은 계속 작동.
- 배터리에서 직접 요청한 위키 생성과 CLI 협업은 실행 가능. ‘자동’과 ‘직접 요청’ 시작 이유 표시.
- 실패·보류·상태 미확인·실행 중을 구분. 오래된 작업을 AI가 조용히 계속 재시도하지 않음.
- 자원 수치는 앱/자식 CLI/분석별 범위와 수집 시각 명시. 비용 미지원은 0원 표시 금지.
- 직접 입력으로 자동 배정 예산보다 많은 CLI가 활성화되어도 키 입력을 가로채지 않음. 관측한 수를 표시하고 새 자동 배정만 보류. 내장/외부 실행 관측 한계를 표시.
- 완료 기준: 사용자가 무엇이 배터리를 쓸 수 있는지, 왜 시작됐는지, 어떻게 멈추는지 알 수 있음.

## F14 — Pinloom에서 가져오기·백업 복구

### F14-A — Pinloom 가져오기

S00/S13 → S14 원본 목록 → 경로 매핑 → 시험 가져오기 → 건수/누락/관계 검증 → 활성화 → S07~S09 열람.

- 실행 중 SQLite의 일관된 snapshot, Markdown/첨부 목록과 해시. 원본 DB 쓰기 없음.
- source namespace/ID로 재시도 중복 방지. unsupported 항목을 목록에 남기며 몰래 버리지 않음.
- Teams 관계는 이력/재사용 후보로 보관. 가져오기 즉시 역할 실행/자동 위키/임베딩 시작 금지.
- provider 로컬 기록이 없는 대화는 열람만 가능하다고 표시. Pinloom이 관리 중인 프로세스를 임의로 인수하지 않음.
- 완료 기준: 가져오기를 중단하거나 되돌려도 Pinloom이 그대로 사용 가능. 활성 데이터로 전환하기 전 검증됨.

### F14-B — Runwick 백업 만들기

S13 → S14 백업 만들기 → 대상/포함·제외/저장 위치 확인 → 일관된 snapshot·문서·첨부 묶음 → manifest와 해시 확인 → 백업 파일 열기.

- 실행 중 CLI를 종료하지 않음. 계속 기록되는 원문과 편집 문서에 대해 백업 시점·검증 결과를 명시. 일관성 확보 실패나 디스크 부족은 완료로 표시하지 않음.
- 비밀값·프로세스 메모리·파생 인덱스는 제외 목록. 보안 저장소를 사용할 수 없는 다른 기기에서는 인증 재설정이 필요함을 복구 보고에 표시.
- 완료 기준: 생성한 백업을 별도 데이터 영역에서 열어 원문·핀·관계·문서·첨부 해시를 검증할 수 있음.

### F14-C — 백업 복구·활성 전환

S14 백업 선택 → 버전/무결성 검사 → 별도 영역 복원 → 경로 재매핑 → 검증 미리보기 → 기존 실행/미저장 편집 확인 → 활성 전환.

- 지원하지 않는 버전이나 해시 오류는 기존 데이터에 영향 없이 중단. 실패한 복구본을 활성화하지 않음.
- 관리 실행·미저장 편집이 남아 있으면 복구본 열람은 가능하지만 활성 전환은 보류. 사용자 선택으로 실행 종료·편집 보존 후 전환.
- 전환 전에 기존 저장소를 보존하고, 전환 실패 시 기존 저장소 유지. 과거 실행은 ‘종료/재개 확인 필요’로 취급하며 자동 재시작하지 않음.
- 완료 기준: 현재 기록을 잃지 않고 백업을 검증·선택할 수 있으며 복구 후에도 기록 보기와 CLI 재개가 구분됨.

## F15 — 반복 작업 방식·개인화

S04의 작업 방식 저장 또는 S13 역할/설정 → 지시문·선호 도구·선택 절차 검토 → 저장 → 다음 CLI 위임에서 사용.

- template는 세션/실행의 복제가 아님. 필요하지 않은 역할은 생략 가능하고 실제 선택은 활동에서 확인.
- AI가 배치/단축키 변경을 제안하면 미리보기·적용·되돌리기. 작업 중인 화면을 제안만으로 교체하지 않음.
- 설정 변경은 버전으로 기록하며 진행 중 실행의 권한을 조용히 확대하지 않음.
- 완료 기준: 반복 설정은 줄어들지만 template 사용이 일반 세션 시작 조건이 되지 않음.

## 구현 순서와 전체 기획의 관계

전체 기획은 위 기능을 연결해서 다룬다. 구현은 다음과 같이 나눌 수 있지만 출시 범위를 지금 확정하는 표가 아니다.

1. **기반 실험:** 실제 CLI 입력/IME/색상, PTY 생명주기, 원문 ID, 같은 대화 새로고침, 명령 전달 확인.
2. **일상 흐름:** 프로젝트/공간·CLI·파일·기록·핀·설정·활동을 함께 검증.
3. **협업 흐름:** 선언 없는 위임·직접 개입·분리·결과·복구를 실제 CLI로 통합 검증.
4. **기억·전환:** 위키/타임라인·자동 분석·Pinloom 시험 이전·백업·UI 완성도 검증.

모의 상태 테스트 통과와 실제 AI 작업 성공, 한글 붙여넣기와 IME 조합 성공, 유휴 성능과 작업 중 배터리를 각각 분리해서 보고한다. Herdr보다 좋다는 평가는 같은 조건의 사용 과제·자원 측정 이후에만 한다.
