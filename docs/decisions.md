AI와 대화하는 경험은 기존 CLI를 선호한다. 동시에 Pinloom에서 유용했던 특정 대화의 핀 고정과, 브라우저 검색으로 찾던 과거 대화 열람 경험을 유지하고 개선해야 한다.

따라서 CLI 사용을 선택했다는 이유로 기록 검색과 핀을 제외하지 않는다. CLI 실행 화면과 별도로 검색·핀·앞뒤 문맥을 읽는 기록 패널을 두는 방식은 현재 추천안이다. 패널 배치, 핀 조작 방식, CLI별 기록 수집 방법은 검증 후 구체화한다.

## 2026-11-05 프로젝트 파일 탐색과 문서 편집

**확정 — 사용자 동의**

프로젝트 내부 구성을 파일 트리로 탐색하고, Markdown·일반 텍스트를 간단히 편집할 수 있도록 한다. 같은 프로젝트 화면에서 세션과 파일을 오가고, 중앙 작업 영역에는 터미널·문서를 탭으로 여는 방향에 동의했다. 기록·검색·핀은 필요할 때 여는 패널로 연결한다.

초기 편집 범위는 Markdown·일반 텍스트 편집과 미리보기, 코드 열람·구문 강조, 파일 경로 복사·외부 에디터 열기를 기준으로 구체화한다. 한글 입력·실행 취소·저장·AI의 외부 파일 변경에 대한 충돌 처리를 검증한다. 자동완성·디버거·확장 프로그램은 후속 판단 대상으로 둔다. 구체적인 배치와 에디터 라이브러리는 아직 미정이다.

## 2026-11-05 프로젝트와 작업 공간 및 세션

**확정 — 사용자 결정**

프로젝트 → 작업 공간 → 세션 구조를 채택한다. 프로젝트는 제품이나 저장소, 작업 공간은 작업 폴더와 열린 문서·세션의 묶음, 세션은 개별 Claude·Codex 대화 또는 일반 터미널을 뜻한다.

- 프로젝트를 열면 기본 공간에서 바로 시작한다. 기본 공간을 직접 만들거나 이름 붙이는 절차를 요구하지 않는다.
- 최근 사용한 세션과 문서 화면을 복원한다. 살아 있는 실행에는 재연결하고, 종료된 실행의 재개는 아래 실행 정책을 따른다.
- 새 세션은 현재 공간에 추가한다. 같은 공간의 세션들은 같은 파일을 보며 작업한다.
- 사용자가 독립적으로 작업하려고 할 때 ‘분리해서 작업’으로 별도 worktree와 공간을 구성한다. 모든 세션에 worktree를 강제하지 않는다.
- 분리한 공간은 사이드바에서 작업 이름으로 구분한다. 선택한 공간에 맞춰 파일 트리·문서·터미널을 함께 전환한다.
- 대화 검색은 공간에 한정하지 않고 프로젝트 전체와 전체 기록을 대상으로 할 수 있다.

Git이 아닌 폴더도 기본 공간에서 사용할 수 있다. Git worktree를 통한 분리는 Git 프로젝트에 해당한다. 구체적인 DB 스키마, worktree 정리·통합, 별도 작업 목표·검토 객체의 도입 여부는 아직 확정하지 않았다.

## 2026-11-05 창 닫기와 실행 종료 및 재개

**확정 — 사용자 결정**

| 사용자 행동 | 동작 |
| --- | --- |
| 창만 닫기 | 진행 중인 CLI 작업을 유지 |
| ‘작업까지 종료’ 선택 | Runwick이 관리하는 실행 중인 작업을 확인하고 종료 |
| 앱 다시 열기 | 살아 있는 실행에 재연결 |
| 컴퓨터 재부팅 후 열기 | 화면·기록을 복원하고, 재개 가능한 세션은 사용자가 선택해 재개 |

백그라운드 실행이 남아 있으면 실행 중인 작업 수와 종료 수단을 확인할 수 있어야 한다. 메뉴 막대 등 창이 닫힌 상태에서도 접근할 수 있는 진입점을 구체화한다. 기록 열람·화면 복원, 살아 있는 프로세스에 재연결, 종료된 provider 세션 재개를 구분한다. 재부팅 후 이전 명령을 임의로 자동 실행하지 않는다.

이 결정은 실행 수명에 대한 제품 동작이다. 새로운 자동 작업의 시작 조건은 아래 자동 작업 정책을 따른다. 프로세스 분리 구조, 종료 메뉴·단축키의 구체적 연결, 충돌 후 복구 구현은 기술 검증이 필요하다.

## 2026-11-05 기록 저장과 자동 분석 및 배터리 정책

**확정 — 사용자 결정**

| 작업 | 기본 정책 |
| --- | --- |
| 대화 저장·키워드 검색 색인 | 변경된 내용만 자동 반영 |
| AI 위키 정리·타임라인 요약·임베딩 | 프로젝트별로 자동 실행을 켜도록 설정 |
| 배터리 사용 중 새 자동 분석 | 보류 |
| 사용자가 직접 요청한 작업 | 배터리 사용 중에도 실행 |

자동 실행을 켠 프로젝트는 변경이 쌓이고 작업이 한가해졌을 때 처리한다. 실행 이유·진행 상태·최근 결과·중지 수단을 한곳에서 확인할 수 있게 한다. 기본 키워드 검색과 핀은 AI 요약이나 임베딩 실행에 의존하지 않는다.

배터리 정책은 새 자동 분석의 시작을 제한하는 기준이며, 실행 중인 CLI를 자동 종료하는 정책이 아니다. 구체적인 idle 판정, 변경량 기준, 동시 실행 수·재시도·예산 제한, 진행 중인 자동 작업의 전원 변경 대응은 기술 설계에서 구체화한다. 이 정책의 합의가 모든 자동 분석 기능의 첫 출시 포함을 확정한 것은 아니다.

## 2026-11-05 공통 환경변수와 세션 새로고침

**확정 — 사용자 수정 요구**

Runwick의 환경변수 설정은 전체 공통 하나만 제공한다. 앞서 제안한 프로젝트별·이번 실행만 설정은 채택하지 않는다. 프로젝트별 값은 `.env` 등 기존 프로젝트 도구의 설정 방식에 맡긴다. `.env`가 모든 CLI에 자동 반영된다고 가정하지 않으며, 별도 자동 로더를 도입하기로 한 것은 아니다.

환경변수·MCP 설정 변경을 기존 대화에도 적용할 수 있는 **세션 새로고침**을 제공한다. 사용자가 새 대화를 만들거나 재개 명령을 직접 입력하지 않아도, 같은 Runwick 세션과 provider 대화, 핀, 작업 폴더를 유지하며 설정을 다시 적용하는 것이 요구사항이다. 이는 제품 요구사항의 확정이며 기능 구현 완료를 뜻하지 않는다.

구현 제안은 도구별 지원에 따라 설정 재연결 또는 CLI 재시작·기존 세션 ID 재개를 수행하는 방식이다. 재개 가능 여부를 먼저 확인하고, 적용 완료·MCP 연결 실패·인증 필요 상태를 구분한다. 현재 응답을 생성하거나 도구를 실행하는 중이면 현재 작업 완료 후 적용 또는 사용자가 중단 후 적용하는 흐름을 구체화한다. 설정 저장만으로 전체 실행을 일괄 재시작하지 않는다.

공유 daemon의 오래된 환경, 세션별 MCP 연결, 재개 시 모델·권한·작업 경로 보존은 구현 전에 검증한다. 세부 근거와 미검증 범위는 [세션 새로고침 조사](research/session-refresh.md)에 기록했다.

## 2026-11-05 전체 제품 기획과 협업 사용성 검토

**확정 — 사용자 요청과 검토 방향**

- 구현 범위를 먼저 줄이기보다 전체 제품을 상세하게 기획하고, UI 디자인이 가능하도록 화면·흐름·상태까지 정리한다.
- Pinloom의 팀·오케스트레이션 구조를 그대로 전제하지 않는다. Herdr의 코드를 읽고 팀 선언이 필요 없는 실행 구조와 전체 사용성을 비교한다.
- Pinloom의 자체 제약 중 실제 실행 충돌을 막는 조건과 사용 절차만 늘리는 조건을 구분한다. 더 자연스러운 설계를 찾는 것이 목적이다.

이를 바탕으로 [전체 제품 기획](product-spec.md), [협업 설계](orchestration.md), [화면 명세](ui-spec.md), [사용 흐름](user-flows.md)을 **사용자 검토용 초안**으로 작성했다. 추천안은 기존 CLI 한 세션에서 시작하고 위임이 생기면 협업 관계·작업 기록이 붙는 방식이다. 팀 생성이나 별도 목표 등록은 필수로 요구하지 않는다.

이 추천 모델의 AI 자율 범위, 실행 한도 기본값, 부모 종료 시 자식 처리, 자동 위키 반영 범위, 세부 UI는 아직 사용자 결정으로 기록하지 않는다. 구현 순서는 전체 기획 범위와 별도로 정한다.

## 2026-11-06 Orca·Tailscale 원격 사용성 검토

**조사 요청 당시 기록 — 이후 방향 합의는 다음 항목 참고**

사용자는 Orca로 기억하는 도구에서 Tailscale을 통한 쉬운 원격 전환이 장점으로 언급되는지 확인하고 Runwick 적용 가능성을 검토해 달라고 요청했다. [Orca·Tailscale 조사](research/orca-remote.md)에 공식 문서·고정 revision 코드·사용 흐름·기존 기획 영향과 미검증 항목을 기록했다.

추천은 실행 호스트가 세션과 파일을 소유하고, 같은 네이티브 GUI에서 로컬/원격 공간을 선택하는 방식이다. Tailscale은 추천 연결 수단으로 활용하되 필수 종속으로 정하지 않는다. 기존 로컬 실행의 기기 간 이동, 비밀값/인증 동기화, 모바일 전체 앱은 이 요청으로 확정하지 않는다. 원격 기능의 출시 포함 여부·페어링/SSH 방식·공통 설정과 지식의 원격 소유권은 별도 검토한다.

## 2026-11-06 여러 기기 실행과 자연스러운 전환

**확정 — 사용자 동의**

Herdr처럼 각 기기가 실행을 유지하는 기반과, 기기 등록을 간단하게 만드는 사용성을 결합한다.

- 로컬에서는 기기 등록 없이 바로 시작한다.
- 원격 기기를 추가하면 기존 사이드바에서 해당 기기의 작업 공간을 함께 보고 선택한다.
- 각 기기가 자신의 실행을 유지하고, GUI는 선택한 공간의 터미널·파일을 보여준다. 클라이언트의 연결 해제와 원격 작업 종료를 구분한다.
- 기존 프로젝트 → 작업 공간 → 세션 구조를 유지하고, 작업 공간에서 실행 기기를 식별한다.

이는 제품 방향의 합의다. Herdr Core 자체 채택, 특정 SSH/링크/QR 구현, Tailscale 필수 사용, 원격 인증·비밀값 동기화, 모바일 앱, 출시 순서까지 확정한 것은 아니다. 상세 설계와 2기기 검증은 [원격 조사](research/orca-remote.md)를 기준으로 이어간다.

## 2026-11-06 구현 착수와 앱 안의 이전 기능

**확정 — 사용자 요청**
