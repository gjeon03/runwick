# UI 디자인 시안

2026-11-06 Claude Design 캔버스 Version 63을 그대로 옮긴 사용자 검토용 시안이다. 이 시안을 바탕으로 앱을 구현했다(구현에서 달라진 점은 [결정 기록](../decisions.md) 2026-11-06 항목). 사용자는 시각 스타일(Graphite Wick)이 마음에 든다고 확인했다. 화면 구성과 정책 표현은 [화면 명세](../ui-spec.md)·[사용 흐름](../user-flows.md)·[결정 기록](../decisions.md)을 바탕으로 한 제안이며, 승인된 구현 결정이 아니다. 시안에서 새로 정한 부분은 [6절](#6-시안에서-정한-것)에 따로 모았다.

## 1. 보는 방법

[index.html](index.html)을 브라우저로 연다. 캔버스와 같은 줄 순서로 모든 화면의 미리보기가 나오고, 누르면 해당 화면이 열린다. 화면 안의 버튼·탭·링크는 시안처럼 동작한다. 서버나 설치는 필요 없다.

| 파일 | 내용 |
| --- | --- |
| `index.html` | 전체 화면 목록. 줄 제목과 화면 미리보기 |
| `screens/*.dc.html` | Claude Design 원본 화면 59개(흐름 51개 + 공통 부품 8개). 각각 브라우저로 바로 열린다 |
| `screens/support.js` | 원본 화면을 오프라인에서 그리는 보기용 실행기. 공통 부품의 사본을 담고 있다 |
| `screens/canvas.json` | 캔버스 배치·제목. Claude Design으로 다시 불러올 때 쓴다 |

- 휴대폰·좁은 화면·공통 부품은 설계한 크기의 틀 안에 보여 준다. 위쪽 `창 크기에 맞춰 보기`를 누르면 창 전체 폭으로 연다.
- 글꼴은 Google Fonts(Geist, JetBrains Mono)를 불러온다. 인터넷이 없으면 시스템 글꼴로 보인다.
- 화면 파일을 고치면 바로 반영된다. 공통 부품(`Sidebar`, `Titlebar` 등)을 고치면 `support.js` 안의 사본도 함께 바꿔야 다른 화면에 반영된다.
- 원본 캔버스: <https://claude.ai/artifact/49g1gPju8KTgY1enVvYQkX> (소유자 계정에서만 열린다)

## 2. 시각 기준 — Graphite Wick

흑연색 작업실에 심지 불씨 하나. 터미널이 주인공이고, 사람이 봐야 할 때만 불씨 색(ember)이 켜진다. 실제 값은 [시각 기준 화면](screens/Foundations.dc.html)에 있다.

**원칙**

- 상태는 색·모양(아이콘)·글자로 함께 표시한다. 색만으로 구분하지 않는다.
- 패널은 테두리보다 바탕 명도 차이로 구분한다.
- 선택, 키보드 포커스, 실행 중은 서로 다른 표시다. 실행 중은 심지처럼 천천히 깜빡이고, 동작 줄이기 설정에서는 멈춘다.
- 주 행동 버튼만 ember로 채운다. 보조 행동은 회색 바탕이다.

**바탕**

| 용도 | 값 |
| --- | --- |
| 터미널 | `#0B0C0E` |
| 창 | `#0F1012` |
| 문서·설정 본문 | `#101114` |
| 탐색(사이드바) | `#15161A` |
| 패널 | `#17181C` |
| 행 | `#1F2025` |
| 조작(보조 버튼) | `#26272D` |
| 구분선 | `#25262B` |

**글자**: `#EDEDF0` 본문 강조 · `#D6D7DC` 본문 · `#B0B1B8` 보조 · `#8E8F98` 설명 · `#6F7078` 비활성

**상태 색**

| 상태 | 색 | 쓰임 |
| --- | --- | --- |
| 답변·승인 필요 | `#FF8B3E` ember | 사람이 해야 할 일. 주 행동 버튼 |
| 복구 필요·중지 | `#FF7B86` | 실패, 멈추기 확인(바탕 `#2A1719`) |
| 새 결과·AI | `#74B7FF` | 새 결과, AI 요약·제안 |
| 실행 중·정상 | `#5AD6A4` | 실제 관측한 실행, 연결됨, 통과 |
| 직접 조작 중 | `#BBA2FF` | 내가 입력권을 가진 작업자, 이 Mac에만 있는 초안 |
| 확인 필요 | `#F2C66D` | 버전 불일치, 일부만 받은 기록, 이전 버전 검증 |
| 대기·보류·연결 끊김 | `#9B9CA5` | 이유를 함께 표시 |

**글자 크기**: 화면 제목 22–24 · 패널 제목 15 · 본문과 목록 13 · 보조 정보 12 · 경로·터미널 12.5(JetBrains Mono). 한글은 시스템 글꼴(Apple SD Gothic Neo)로 이어진다.

## 3. 공통 화면 구조

| 영역 | 내용 |
| --- | --- |
| 제목 막대 | 프로젝트 / 공간(원격이면 기기 표시) / branch, 명령 검색(⌘K), 확인할 일·실행 수, 설정 |
| 사이드바 264 | 프로젝트 → 작업 공간 → 세션·파일. 맨 아래 기록·위키·타임라인. 기기를 등록하면 원격 공간에 기기 표시와 기기 필터가 생긴다 |
| 중앙 | 탭 → 터미널(원래 CLI 화면) → 세션 바(상태·협업·확인 필요·새로고침) |
| 우측 패널 380 | 협업·기록·결과 상세. 중앙 폭이 좁아지면 덮개 패널 |
| 설정 | 왼쪽 분류(일반·CLI 도구·공통 환경변수·MCP·협업·역할·자동 작업·기기·저장·가져오기) + 본문 |

좁은 화면은 [폭 1100](screens/Narrow1100.dc.html)에서 우측 패널을 덮개로, [폭 860](screens/Narrow860.dc.html)에서 사이드바를 아이콘 열로 접는다.

## 4. 시안의 예시 데이터

모든 화면은 같은 이야기로 이어진다. 이름과 수치는 예시다.

- **payments-api**: 기본 공간에서 Claude Code로 로그인 만료 오류를 고치고, Codex 회귀 검토와 `auth-tests` 공간의 테스트 작성을 맡긴다. 집 Mac mini의 공간에서는 결제 웹훅 재시도를 구현한다.
- **docs-site**: 즐겨찾기한 두 번째 프로젝트.
- **사내 정산 리포트 자동화 및 문서 정리 프로젝트**: 긴 한글 이름을 확인하는 프로젝트. 야간 배치 공간은 개발 서버에 있다.
- **기기**: 이 Mac(MacBook Pro, 배터리 사용 중), 집 Mac mini(연결됨, 전원 연결), 개발 서버(Runwick 버전이 달라 09:12 이후 연결 안 됨).

## 6. 시안에서 정한 것

기획 문서에 없거나 상세가 열려 있던 부분을 시안에서 정했다. 모두 검토할 제안이다.

**시각과 구조**

- Graphite Wick 색·글자 체계와 상태 색 7종. 스타일 방향은 사용자가 확인했다.
- 위키 관계 그래프는 사용자 요청으로 추가했다. AI 유사 연결은 확인 전까지 제안으로 표시하고 `링크로 연결`/`관련 없음`으로 정리한다.
- 타임라인 모아보기의 프로젝트×요일 격자는 Pinloom 타임라인을 참고했다.

**여러 기기**([원격 검토](../research/orca-remote.md)의 UI 영향과 [결정 기록](../decisions.md) 2026-11-06 기준)

- 실행 기기는 공간 이름 옆의 작은 표시로 보여 준다. 기기 필터는 사이드바 위쪽 아이콘이며 기기를 등록했을 때만 보인다. 이 Mac의 공간과 기록에는 표시를 붙이지 않는다.
- 기기 추가는 Tailscale에서 찾은 기기 또는 SSH 주소로 시작하고, 처음 보는 기기는 지문을 확인한다. 첫 실험 방향을 따른 것이며 연결 방식은 정해지지 않았다.
- 원격 기기에는 실행을 유지하는 부분만 설치하고 화면 앱은 설치하지 않는 것으로 썼다.
- 연결 끊김은 원인(네트워크·잠자기·버전 불일치)을 나눠 보여 주고 AI 작업 실패와 구분한다.
- 위키는 프로젝트마다 보관 기기를 하나 두고, AI 정리도 한 기기가 맡는다. 맡은 기기가 꺼져 있으면 다른 기기가 대신 돌리지 않는다.
- `runwick://home-mac-mini/...` 링크 형식은 자리표시용 예시다.
- 활동 목록에 `상태 확인 불가` 묶음을 두어 `복구 필요`와 구분한다.
- 백업은 기기마다 그 기기 디스크에 만들고, 이 Mac으로 한 부 받아 오는 것은 선택이다.
- 모바일은 확인·답하기·중지만 그렸다. 채택은 별도 판단이다.

## 7. 아직 그리지 않은 것

- **밝은 테마**: 어두운 테마만 그렸다. [화면 명세](../ui-spec.md)는 밝은/어두운 테마를 따로 검증하라고 한다.
- **빈 상태·로딩**: 화면 명세 6절은 묶음마다 정상·빈 상태·로딩·실패·부분 성공·좁은 화면을 요구한다. 빈 상태와 로딩은 일부 화면에만 있다.
- **요구사항 대조**: [사용 흐름](../user-flows.md)의 요구사항 추적표와 화면을 한 줄씩 맞춰 보지 않았다.
- **원격 세부 화면**:
  - 원격 세션 새로고침의 상세 진행(S12)
  - 원격 개발 서버 포트를 이 Mac에서 여는 미리보기
  - 실행 중인 세션을 다른 기기로 옮기는 인계
  - 기기 등록 해제 뒤 남은 공간 표시
- **열린 결정**: 연결·페어링 방식, Tailscale 필수 여부, 자격 증명 동기화, 모바일 채택, 출시 범위, Rust UI 프레임워크([결정 기록](../decisions.md)).
