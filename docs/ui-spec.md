# Runwick 화면·상태 명세

상태: **UI 디자인용 상세 초안 · 시각 스타일과 구현 기술 미확정** · 2026-11-05

기능 기준은 [전체 제품 기획](product-spec.md), 협업 동작은 [협업 설계](orchestration.md)다. 화면 ID는 디자인 프레임과 테스트 시나리오에서 공통으로 사용한다. 별도 팀 관리 화면이나 필수 목표 등록 화면을 만들지 않는다.

## 1. 정보 배치

| 영역 | 기본 내용 | 전환·보존 규칙 |
| --- | --- | --- |
| 좌측 탐색 | 프로젝트 검색, 전체/별, 프로젝트·작업 공간. 선택 공간의 세션/파일 전환 | 영역 폭 조절. 프로젝트·공간 전환 시 중앙 탭과 파일 루트를 함께 전환 |
| 중앙 | 실제 CLI 터미널 또는 문서 탭, 필요하면 좌우/상하 분할 | 중앙이 주 작업 영역. 협업자가 늘어도 모든 탭을 자동 열지 않음 |
| 우측 상세 | 기록/핀, 협업, 변경·결과 중 사용자가 연 항목 | 기본 닫힘. 선택 항목과 필터 유지, 닫아도 실행/검색 상태 유지 |
| 전역 활동 진입점 | 답변 필요·오류·새 결과·실행 수 | 클릭하면 S06. 창이 닫혀도 메뉴 막대에서 접근 |
| 공간 도구 | 새 CLI, 분리해서 작업, 기록, 위키, 타임라인 | 도구는 선택 공간/프로젝트 범위가 보이도록 배치 |

위키·타임라인은 읽을 공간이 필요하므로 중앙 문서형 탭으로 열린다. 해당 화면을 열어도 실행 중인 CLI 탭은 유지한다. ‘세션/파일’은 탐색 방식 전환이며 개발/기획/디자인 같은 별도 앱 모드가 아니다.

폭 후보: 좌측 264, 우측 380 논리 픽셀. 중앙의 사용 가능 폭이 520보다 작아지면 우측 상세를 덮개 패널로 전환한다. 더 좁아지면 좌측도 접을 수 있게 한다. 이는 디자인 비교를 위한 시작값이며 플랫폼별 실제 입력·가독성 시험 후 확정한다. 1440/1100/860 폭에서 같은 흐름을 설계한다. 사이드바 전체의 가로 스크롤은 허용하지 않고 중앙 코드/터미널은 필요에 따라 수평 이동할 수 있다.

## 2. 공통 시각·입력 원칙

- 네이티브 작업 도구의 밀도를 유지하되 모든 칸에 굵은 테두리를 두지 않는다. 패널 계층은 간격·약한 배경 차이로 구분한다. 브랜드 강조색·타이포그래피는 시안에서 결정한다.
- 선택, 키보드 포커스, 실행 상태는 서로 다른 표시다. 상태는 색뿐 아니라 아이콘·텍스트·접근성 이름을 제공한다.
- 한글 긴 프로젝트명·두 줄 결과명·영문 경로가 섞인 행을 디자인 fixture로 쓴다. 말줄임에는 전체 이름/경로를 확인할 수단을 제공한다.
- CLI ANSI 색상·원래 입력 UI를 보존한다. 앱 테마 변경이 터미널 출력을 단색으로 만들면 안 된다. 밝은/어두운 테마와 16/256/truecolor 출력은 별도 검증한다.
- 가짜 진행률·매 답변마다 동일한 5단계 표시는 없다. 실제 단계가 보고되면 상세에서 표시하고 평소에는 현재 행동·경과·마지막 업데이트만 보여준다.
- 활동 상세와 세션 배지는 같은 데이터의 요약/확장이다. 동일한 진행 카드를 대화 맨 위와 고정 헤더에 중복 배치하지 않는다.
- 알림은 현재 입력을 빼앗지 않는다. 클릭하면 해당 요청으로 이동하고, 작업이 이미 끝났으면 현재 결과를 보여준다.
- 모든 목록은 키보드 이동·검색·포커스 복귀를 지원한다. 아이콘 전용 버튼에는 이름과 툴팁을 둔다.

## 4. 화면별 상세 계약

### S00 — 첫 시작·프로젝트 열기

주 행동은 `폴더 열기`, 보조 행동은 `Pinloom 기록 가져오기`다. Rust/PTY/DB 설정 같은 구현 용어를 시작 화면에 노출하지 않는다. 사용 가능한 Claude/Codex/셸과 설치·인증 상태를 보여주되 도구 설치가 안 되어도 파일·기록은 열 수 있다.

- 폴더 선택 → 경로 확인 → 기본 공간 생성 → S01/S02. 프로젝트 이름은 폴더명 기본, 나중에 변경 가능.
- 동일 폴더를 다시 열면 기존 프로젝트로 이동한다. 같은 저장소의 worktree는 별도 프로젝트 후보로 중복 생성하지 않고 연결할 공간을 보여준다.
- 폴더 없음/권한 없음은 해당 경로와 다시 선택하기를 표시. 연결 실패가 과거 기록 열람을 막지 않는다.
- 선택적으로 협업 정책을 한 줄 설명하고 설정에서 바꿀 수 있게 한다. 팀 편성·위키 분석·임베딩을 시작 마법사에서 강제하지 않는다.

### S01 — 기본 작업실·탐색

상단에 프로젝트 검색과 `전체 / ☆` 필터를 둔다. 별 아이콘에는 ‘즐겨찾기’ 이름을 제공한다. 프로젝트 행에는 이름·공간 수·확인할 일 배지, 펼친 공간에는 이름·branch·실행 상태를 표시한다. 경로는 보조 정보로 확인한다. 즐겨찾기에서 별을 해제해 현재 항목이 사라져도 중앙 작업을 종료하지 않는다.

- 선택 공간의 목록은 `세션 / 파일`. 세션 행은 제목·CLI·진행·마지막 시각. 필요 시 대표 아래 작업자를 접어서 표시한다.
- 빈 즐겨찾기는 별 등록 방법과 전체 보기. 필터 결과 없음과 아직 프로젝트 없음은 다른 상태다.
- 최근 공간 복원이 실패하면 경로 연결하기와 저장된 기록 열기를 제공한다.
- 공간을 전환해도 미저장 문서와 실행은 유지한다. 다른 공간의 문서를 같은 이름으로 잘못 저장하지 않도록 탭에 실제 공간을 연결한다.

### S02 — CLI 세션

탭에는 제목·도구 아이콘·상태·미확인 배지를 둔다. 탭 제목을 AI가 변경했어도 사용자가 지정한 이름을 덮어쓰지 않는다. 중앙에는 실제 CLI를 그대로 보여준다. 세션 도구에 `기록`, `핀`, `새로고침`, `더 보기`를 둔다. 협업이 있을 때만 요약 진입점을 추가한다.

| 상태 | 표시·행동 |
| --- | --- |
| 시작 중 | 실행 도구와 경과, 취소. 오래 걸리면 마지막 단계/출력 확인 |
| 실행/입력 중 | CLI 고유 UI 유지. 앱 상태는 실제 관측한 범위만 표시 |
| 인증·신뢰·승인 필요 | 해당 CLI 화면을 중심에. 인식 불가이면 일반 승인 버튼 생성 금지 |
| 연결 끊김 | 마지막 출력은 유지, 재연결 상태와 현재 생존 확인 |
| 실행 종료 | 출력·기록 유지, 지원 시 동일 대화 재개, 일반 셸은 새 실행을 별도 명시 |
| 기록 수집 지연/실패 | 비차단 상태 표시, 마지막 수집 시각·재시도. CLI 계속 사용 가능 |

`탭 닫기`는 화면에서만 숨기며 실행·기록을 유지하는 추천안이다. 메뉴에서 `실행 종료`를 분리하고 대상/자식 영향을 보여준다. 마지막 탭을 닫아도 저장된 세션 목록이 남는다. `새 대화`와 `같은 대화 재개`는 분리한다. 결과 완료 후 빈 완료 전용 탭을 자동 생성하지 않는다.

### S03 — 파일·문서

현재 공간의 파일 트리와 파일명 검색을 제공한다. 문서를 클릭하면 중앙 탭, 보조 행동으로 나란히 열기·경로 복사·외부 에디터를 제공한다. Markdown/일반 텍스트는 편집, 코드 파일은 우선 열람·구문 강조를 지원한다. 새 문서는 이름·위치를 정해 텍스트/Markdown으로 만들 수 있다.

- 문서 헤더: 실제 경로/공간, 미저장 표시, 편집/미리보기, 저장 상태.
- 외부 변경 + 로컬 수정 없음: 새 버전을 반영하고 변경 표시.
- 외부 변경 + 미저장 편집: 비교 화면에서 내 편집·디스크 내용·기준 버전을 확인. 선택 저장 전 최신 파일 버전을 재확인.
- 공간 전환은 미저장 버퍼 보존. 문서 닫기/앱 종료는 저장·편집 유지·명시적 버리기 흐름. 일반 창 닫기는 버퍼도 복원 가능하게 유지.
- 바이너리·너무 큰 파일·읽기 불가: 이유·크기·외부 열기. 전체 파일을 무조건 메모리에 로드하지 않음.
- 파일 삭제·폴더 제거는 초기 가벼운 편집의 필수 행동이 아니다. 제공할 경우 실행/문서 연결에 미치는 영향을 별도로 설계한다.

### S04 — 협업 상세

처음 위임될 때 해당 세션에 붙는 우측 상세다. 상단에는 요청의 짧은 제목, 현재 상태, 진행 중/확인 필요 수, `새 배정 보류`와 더 보기. 본문 기본은 실행 목록이며 그래프 편집기가 아니다.

보류 시 버튼은 `배정 재개`로 바뀌고, 이미 실행 중인 수와 미전달 대기 수를 따로 표시한다. 대기 요청은 개별 취소 가능하다. 재개하면 경로·의존 결과·입력권·설정/권한을 다시 확인하고 전제가 바뀐 요청은 ‘재검토 필요’로 남긴다. 보류 중 수집한 결과는 열람할 수 있지만 자동으로 새 턴을 시작하지 않는다.

각 행: 맡긴 일, 역할 표시명, 실제 CLI/모델(알 수 있을 때), 공간/branch, 현재 행동, 마지막 보고, 결과 링크. 누르면 S05 또는 결과 S11. 연결된 할 일이 있으면 `선행 작업 대기: API 변경`처럼 구체적으로 표시한다. 구조화된 단계가 없으면 목록만 보여준다.

- 상세에서 요청 원문·시도 이력·사용 설정 버전·전송 확인·측정 가능한 시간/사용량을 펼친다.
- 바쁜 작업자에 후속 지시: 대기열에 추가, 중단하고 전송은 별도 선택. 기존 요청 자동 취소 없음.
- 다른 프로젝트 작업자는 프로젝트/공간 경로를 항상 표시. 소속이 화면에서만 바뀌었다고 파일도 이동한 것처럼 보이지 않음.
- `작업 방식 저장`은 선택 행동. 역할·지시문·선호 도구만 저장하고 기존 세션 ID·비밀값은 복제하지 않음.
- 전체 중단 버튼은 영향받는 실행과 별도 독립 실행을 보여준다. 실행이 실제 멈추기 전에는 완료/중단으로 단정하지 않음.

### S05 — 작업자 잠깐 보기·직접 개입

대표 화면 위에 작업자 터미널을 잠깐 연다. 헤더에 맡긴 일·실제 공간·상태, `직접 대화`, `탭에 유지`, 닫기를 둔다. 최초 미리보기는 입력 비활성으로 잘못된 키 전달을 막고, 직접 대화를 누르거나 명확한 입력 전환 행동 후 활성화한다.

직접 조작 중에는 자동 지시가 대기한다. `다시 맡기기`로 반환하면 사용자가 추가한 지시와 현재 시도가 연결된다. 미리보기 닫기만으로 입력권을 자동 반환하지 않고 상태 배지와 반환 동작을 남긴다. `탭에 유지`는 화면 배치만 바꾸며 부모 관계나 결과 연결을 끊지 않는다.

작업자가 종료되어 실시간 화면이 없으면 마지막 출력·기록·결과를 보여준다. 기록이 없는 provider에는 ‘저장된 원문 없음’을 표시하고 가짜 대화를 구성하지 않는다.

다른 공간의 작업자를 미리보기로 보는 동안에는 선택 공간·파일 트리·중앙 탭을 바꾸지 않는다. 헤더에 작업자의 실제 프로젝트/공간을 표시한다. `탭에 유지`를 선택하면 **작업자가 속한 공간으로 전환하여** 탭을 열고 파일 트리도 그 공간으로 맞춘다. 기존 공간의 문서·배치·입력은 보존하며 이전 위치로 돌아갈 수 있다. 다른 공간의 실시간 세션을 현재 공간 소속처럼 표시하지 않는다.

### S06 — 전체 활동·확인할 일

전역 버튼과 메뉴 막대에서 동일 목록으로 진입한다. 기본 정렬은 내 답변/승인 필요, 복구 필요, 새 결과, 실행 중, 대기. 프로젝트·종류·상태 필터 제공. 사용자 CLI/협업과 자동 분석을 종류로 구분한다.

각 행: 무엇을 하는지, 시작 이유, 프로젝트/공간, 현재 상태, 경과·마지막 업데이트, 다음 행동. 자동 작업에는 전원/idle/실행 한도에 따른 보류 이유를 표시한다. 자원 상세는 앱/관리 실행/분석 작업을 구분하고 수집 시각을 표시한다.

- 질문 클릭 → 실제 요청 S02/S05. stale 요청이면 현재 결과로 이동하고 더 이상 답할 수 없음을 표시.
- 새 결과 확인 → 읽음 처리. 검증 통과/작업 수용으로 자동 변환하지 않음.
- `중지`는 해당 작업에만 적용. `작업까지 종료`는 전체 관리 실행 영향 목록 제공.
- 활동 없음은 ‘실행 중인 작업 없음’과 마지막 저장 상태. AI 자동 작업을 켜라고 강요하지 않음.
- 권한/연결 부족으로 자원 측정이 없으면 미지원으로 표시. 0으로 오인하게 만들지 않음.
- ‘자동 배정 한도’와 관측한 실제 활성 실행 수를 분리한다. 직접 입력으로 한도를 넘으면 기존 CLI는 유지하고 ‘직접 실행 포함 N개 · 새 자동 배정 보류’처럼 표시. 관측 불가 내장 작업은 제외 범위를 명시한다.

### S07 — 기록·검색·핀

우측 패널로 시작하고 긴 기록은 중앙으로 확장 가능하다. 상단 검색 범위는 현재 세션/프로젝트/전체이며 현재 범위를 텍스트로 표시한다. 날짜·도구·핀 필터를 제공한다. 결과 행에는 본문 발췌, 검색어 강조, 프로젝트·세션·시각·도구를 표시한다.

- 클릭 → 해당 메시지와 앞뒤 문맥. 더 읽기는 점진 로드. `실행 열기`/`같은 대화 재개`는 별도 행동.
- 메시지 전체/선택 문장 핀. 터미널 선택 텍스트 핀에는 ‘터미널 발췌’, 메시지 연결 가능 여부를 표시.
- 핀 제목·메모 변경, 원문 보기, 인계에 담기, 핀 해제. 원본 삭제는 제공하지 않음.
- 결과 없음, 수집 중, 일부 기록만 검색, 색인 실패, 원본 없음 상태를 따로 설계.
- Ctrl/Cmd-F 성격의 터미널 화면 검색과 대화 아카이브 검색은 이름과 범위를 구별한다. 오래된 대화는 아카이브에서 찾는다.

### S08 — 위키·변경 제안

중앙 문서 탭에 문서 목록/본문을 구성한다. 제목·수정 시각·근거·수동/AI 제안·검토 상태. 편집/미리보기, 관련 세션, 변경 이력, 인계에 담기. 변경 제안은 이전/제안 diff와 근거를 보고 적용/부분 적용/보류/거절할 수 있다.

빈 위키에는 새 문서·기존 문서 가져오기·선택한 세션으로 초안 만들기. 자동 분석 활성화와 수동 생성은 구분한다. 사용자가 편집한 뒤 도착한 AI 제안은 옛 버전 덮어쓰기를 막고 재비교한다. 출처 충돌은 ‘결정 확인 필요’로 남긴다.

자동 반영 설정을 켜는 경우에는 AI 관리 영역과 수정 범위를 S13에서 명시한다. 자동 생성 실패도 기존 문서를 유지한다.

### S09 — 타임라인·이어하기

날짜 축의 세션·핀·파일 변경·위키 결정·협업 결과를 표시한다. 실제 이벤트와 AI 요약은 표식을 구별한다. 날짜/프로젝트/종류 필터와 세션·원문 링크를 제공한다. 요약이 없는 날에도 실제 이벤트를 보여준다.

이어하기 카드: 마지막 작업, 수동 메모, 선택적 AI 요약, 남은 항목, 관련 세션/핀/파일. 요약의 생성 시각·기준 기록을 표시한다. `살아 있는 실행 열기`, `같은 대화 재개`, `새 대화에 인계`는 각각 다른 행동이다. 프로젝트 폴더가 없어도 기록은 읽을 수 있다.

### S10 — 분리해서 작업·공간 관리

진입점은 공간 메뉴·세션 메뉴·AI의 분리 제안이다. 기본 화면에는 작업 이름, 출발 branch/revision, 새 branch/기존 branch, 예상 경로, 포함할 변경 요약. 고급 옵션을 펼치기 전에도 작업의 실제 기준을 확인할 수 있어야 한다.

만들기 진행: Git 확인 → worktree 생성 → 공간 연결 → 선택 CLI 시작. 각각의 실패 위치를 표시한다. worktree는 생성됐지만 CLI가 실패하면 만들어진 공간을 남기고 CLI만 재시도한다. 기본 공간으로 조용히 돌아가 작업하지 않는다.

준비 명령·필요한 환경·개발 서버 포트는 별도 준비 상태. ‘worktree 생성 완료’를 ‘개발 환경 준비 완료’로 표현하지 않는다. Git이 아니면 분리 불가 이유와 현재 공간에서 작업을 제공한다.

공간 보관은 목록만 접는다. 폴더 제거는 실행 중 세션, 미저장 문서, dirty/untracked, 미푸시 결과를 확인하는 별도 흐름이다. 결과 연결과 대화 기록은 공간 제거 뒤에도 남긴다.

### S11 — 변경·결과·검증

중앙 또는 우측에서 해당 시도의 결과를 연다. 요약, 파일/문서 경로, 원문, 비교 기준과 현재 revision, 변경 목록, 검증 결과, 미완료 사항을 보여준다. `폴더/파일 열기`, `경로 복사`, `검토 요청`, `이어서 수정`, `통합 준비`가 문맥에 맞게 나타난다.

다른 공간의 결과는 현재 화면에서 읽기 전용 상세로 볼 수 있고 실제 출처를 표시한다. `파일 열기/편집`은 소유 공간으로 전환한 뒤 S03에서 열어 파일 트리·문서 경로를 일치시킨다. 해당 공간/파일이 없어졌으면 보관한 결과 스냅샷을 읽기 전용으로 보여주고 경로 재연결을 제공한다. 현재 공간의 같은 이름 파일을 대신 열지 않는다.

| 상황 | 주 행동 | 반드시 남길 정보 |
| --- | --- | --- |
| 결과 있음·검증 없음 | 결과 보기/검토 요청 | 미검증 표식 |
| 일부 결과 후 실패 | 이어서 수정 | 초안·오류·완료한 단계·시도 이력 |
| 검증 실패 | 실패 확인/수정 요청 | 명령·대상 revision·로그 |
| 검증 후 파일 변경 | 현재 버전 다시 확인 | 이전 검증을 통과로 재사용하지 않음 |
| 통합 충돌 | 충돌 확인/해결 맡기기/보류 | 출발/대상·미해결 파일·현재 공간 |
| 완료 | 결과/기록 유지 | 별도 빈 완료 화면으로 대체하지 않음 |

`처음부터 다시`는 보조 행동이며 기존 시도를 삭제하지 않는다. 사용자가 결과를 ‘확인함’과 검토자가 ‘검증 통과’한 상태는 별도다. 원격 push/PR/배포는 버튼 이름·대상·이전 지시 범위를 명확히 하고 로컬 통합에 끼워 넣지 않는다.

### S12 — 세션 새로고침

S02 메뉴 또는 S13의 설정 변경 대상 목록에서 진입한다. 적용할 공통 환경 버전·MCP 변경 종류, 현재 대화/작업 공간, 현재 실행 상태를 보여준다. 비밀값은 diff에 표시하지 않는다.

- 대기 중: 사전 확인 후 적용.
- 작업 중: `현재 응답 후 적용` 추천, `중단하고 적용` 선택. 대기 예약 취소도 제공.
- 사전 확인 실패: 기존 실행 유지, 대화 ID 없음/경로 없음/재개 미지원 등 실제 이유.
- 진행: 기록 저장 → 필요한 재연결 또는 재시작 → 동일 대화 재연결 → 설정/연결 확인. 필요 없는 단계는 표시하지 않음.
- 일부 실패: 환경 적용·MCP 연결·인증 각각의 상태, 같은 세션에서 재시도. 새 대화 자동 생성 금지.

일반 셸은 프로세스 상태를 대화처럼 보존할 수 없으므로 별도의 재시작 동작으로 명시한다. CLI 입력 초안을 보존할 수 없는 경로는 중단 전에 알려주고 복사할 수 있게 한다. 무관한 세션은 이 흐름으로 재시작하지 않는다.

### S13 — 설정·도구·작업 방식

| 분류 | 표시와 행동 |
| --- | --- |
| 일반 | 테마·폰트·배치·단축키·창/종료 정책 설명 |
| CLI 도구 | 설치 버전, 실행 경로, 인증, 기록/협업/재개 지원 수준, 테스트 결과 |
| 공통 환경변수 | 키·마스킹된 값·설명·저장 상태·적용 대기 세션. 프로젝트/이번 실행 탭 없음 |
| MCP | provider별 실제 설정 위치/범위, 연결·인증 상태, 변경·새로고침 대상 |
| 협업 | 자율 범위, 허용 도구/프로젝트, 자동 배정 한도와 관측 제외 범위, 기본 작업 방식. 범위를 넓히는 변경은 진행 중 작업에 자동 소급하지 않음 |
| 역할/작업 방식 | 지시문·선호 도구·선택 절차, 미리보기·복제·저장. 실제 팀 멤버 목록 아님 |
| 자동 작업 | 프로젝트별 위키/타임라인/임베딩 opt-in, 자동 반영 범위, 배터리 정책, 최근 결과 |
| 저장·가져오기 | 저장 위치·사용량·백업·복구·기록 보관 정책, S14 진입 |

환경 설정이 저장됐다는 표시와 현재 CLI에 적용됐다는 표시는 구분한다. 저장 시 전체 세션 강제 재시작은 없다. 역할/배치의 AI 제안은 변경 미리보기와 되돌리기 수단을 갖추고 사용 중인 화면을 즉시 뜯어고치지 않는다.

### S14 — 가져오기·백업·복구

원본 선택 → 읽기 전용 목록/용량 확인 → 프로젝트 경로 매핑 → 시험 가져오기 → 종류별 검증 보고 → 활성화 순서다. 지원/미지원/누락·중복·관계 오류를 보이며 비밀값·본문을 일반 로그에 출력하지 않는다.

Teams 이력은 과거 관계로 보관하고 역할/작업 방식으로 변환할 수 있는 후보를 보여준다. 가져왔다는 이유로 팀이나 CLI를 자동 실행하지 않는다. provider 재개 가능 여부는 별도 상태다.

중단된 배치는 활성 데이터와 섞이지 않으며 재시도는 동일 원본을 중복 생성하지 않는다. 백업 복원은 활성 저장소를 덮기 전에 별도 복구본에서 검사하고 현재 데이터 보존 경로를 제공한다. 내보내기에는 포함/제외 목록이 있어야 한다.

백업 만들기는 대상·저장 위치·예상 용량·포함/제외 항목 확인 → 일관된 snapshot과 파일 묶음 생성 → manifest/해시 검증 → 완료/파일 열기의 흐름이다. 생성 중 현재 CLI는 유지한다. 원문·핀·문서·관계·설정 참조를 포함하되 비밀값·프로세스 메모리·재생성 가능한 인덱스는 별도로 제외 표시한다. 파일 변경 중 일관성을 확보하지 못하면 실패한 묶음을 정상 백업으로 표시하지 않는다.

복구는 백업 선택 → 무결성/버전 검사 → 별도 데이터 영역에 복원 → 원래 프로젝트 경로 매핑 → 미리보기/비교 → 활성 전환이다. 기존 관리 실행이나 미저장 편집이 남아 있으면 활성 전환은 보류하고 복구본 열람만 가능하다. 사용자가 실행 종료·편집 보존을 선택한 뒤 현재 저장소를 보존한 상태로 전환하며, 실패하면 기존 저장소를 계속 사용한다. 복구한 과거 실행 상태는 이력으로 취급하고 자동 재실행하지 않는다.

| 대화 통합 검색 | Cmd-Shift-F | S07의 마지막 범위로 열고 범위를 항상 표시 |
| 새 CLI 세션 | Cmd-T | 마지막 선택 도구 또는 도구 선택 메뉴 |
| 현재 탭 닫기 | Cmd-W | 숨김/문서 편집 보존 정책 적용. 실행 종료 아님 |
| 문서 저장 | Cmd-S | 편집 문서가 포커스일 때만 |
| 패널 닫기 | Escape | 최상단 앱 패널을 닫고 원래 포커스 복귀. 터미널 자체 포커스에서는 CLI로 전달 |

터미널 포커스의 Ctrl-C/Ctrl-D 등 CLI 키는 그대로 전달한다. IME 조합 중 Enter/Escape/방향키를 앱 명령으로 가로채지 않는다. 패널을 닫으면 원래 입력 위치·선택·스크롤로 돌아간다. 화면 읽기 도구가 상태 변경과 아이콘 버튼의 의미를 이해할 수 있게 한다.

## 6. 디자인 산출물과 검토 순서

하나의 정지 화면으로 완료를 판단하지 않는다. 아래 연결된 프레임 묶음으로 설계한다.

1. **기본 작업:** 첫 시작 → 프로젝트/즐겨찾기 → 실제 CLI → 파일·문서 나란히 → 공간 전환.
2. **협업:** 평소 세션 → 위임 등장 → 작업자 미리보기 → 직접 개입 → 결과 반환 → 결과/파일 확인.
3. **주의·복구:** 승인 필요 → 오래된 요청 → 전달 불확실 → 일부 결과 후 실패 → 이어서 수정.
4. **기억:** 대화 검색 → 원문/핀 → 위키 제안 → 타임라인 → 다음 날 재개.
5. **환경·분리:** 공통 설정 변경 → 응답 후 새로고침 → 일부 MCP 실패; worktree 생성 → 통합 충돌 → 보관.
6. **가벼움·종료:** 자동 작업 보류/실행 → 메뉴 막대 활동 → 창 재연결 → 재부팅 후 재개 선택.

각 묶음에 정상·빈 상태·로딩·실패·부분 성공·좁은 화면을 포함한다. 미리보기 닫기/공간 전환/완료 뒤에 실제 작업이 어디에 남는지 연결선을 붙인다. UI 디자인 완료 판단은 [요구사항 추적표](user-flows.md)의 모든 행이 화면과 예외 흐름을 갖는지로 확인한다.
